# Портирование tg-ws-proxy на Android

В этом документе подробно описано, как устроен оригинальный репозиторий [Flowseal/tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy), почему его нельзя запустить на Android как есть и как именно реализуется его полноценный мобильный порт.

---

## 1. Как устроен оригинал (Анализ кодовой базы)

В репозитории Flowseal логика сосредоточена в каталоге `proxy/`:
- `proxy/tg_ws_proxy.py` — точка входа, конфигурация, запуск TCP-сервера на `127.0.0.1:1443`.
- `proxy/bridge.py` — ядро деобфускации MTProto, определение протокола и создание моста TCP ↔ WebSocket.
- `proxy/raw_websocket.py` — низкоуровневая реализация протокола WebSocket (RFC 6455).
- `proxy/fake_tls.py` — генерация и обработка Fake TLS ClientHello для обхода блокировок handshake.
- `proxy/balancer.py` — выбор и балансировка доступных шлюзов дата-центров Telegram.
- `proxy/cf_h2.py` / `proxy/h2_transport.py` — fallback через HTTP/2 и Cloudflare Worker.

### Протокол MTProto и фаза рукопожатия:
1. **Инициализация соединения:** Telegram при подключении отправляет 64 байта данных.
2. **Тип протокола:**
   - Abridged (`0xefefefef`) — наиболее компактный фрейминг;
   - Intermediate (`0xeeeeeeee`) — 4-байтные префиксы длины;
   - Padded Intermediate (`0xdddddddd`).
3. **Деобфускация (AES-128-CTR):**
   - Первые байты содержат случайный ключ шифрования и вектор инициализации (IV).
   - Если используется секрет (обычный или Fake TLS `ee...`), он подмешивается в SHA-256 для вычисления ключей дешифрования потока.
4. **Определение целевого DC:**
   - После расшифровки стартового пакета в байтах 60–61 содержится номер дата-центра Telegram (DC 1, 2, 3, 4, 5).
5. **Транспорт WebSocket (WSS):**
   - Вместо прямого TCP-подключения к заблокированным IP-адресам дата-центров прокси устанавливает защищённое TLS-соединение на порт 443 к доменам веб-версий Telegram (например, `vesta.web.telegram.org/apiws`, `pluto.web.telegram.org/apiws`).
   - MTProto-пакеты упаковываются в бинарные фреймы WebSocket.
   - Для провайдера трафик выглядит как обычный легитимный HTTPS/WSS-веб-трафик к Telegram Web.

## 2. Почему нельзя использовать оригинальный Python-код на Android

1. **Размер приложения:** Полноценный рантайм Python (через Chaquopy или Termux/Pydroid) добавит к APK от 50 до 90 МБ.
2. **Оперативная память:** Процесс CPython с библиотеками `cryptography`, `asyncio` и парсерами потребляет 40–80 МБ RAM. На бюджетных и среднебюджетных смартфонах система быстро выгрузит его из памяти.
3. **Батарея и фоновый режим:** Python-интерпретатор не оптимизирован под управление энергопотреблением мобильных ОС (Doze Mode). При блокировке экрана сокеты разорвутся, и Telegram потеряет связь.

---

## 3. Архитектура мобильного порта (Go или Kotlin)

Оптимальное решение — переписать логику проксирования на **Go** (рекомендуется) или на чистый **Kotlin**:

```
┌────────────────────────────────────────────────────────┐
│               Клиент Telegram (Android)                │
└───────────────────────────┬────────────────────────────┘
                            │ MTProto over TCP (127.0.0.1:1443)
┌───────────────────────────▼────────────────────────────┐
│      Android Service (TgWsProxy Core на Go/Kotlin)     │
│                                                        │
│  1. net.Listen("tcp", "127.0.0.1:1443")                │
│  2. MTProto Obfuscation Parser (AES-CTR)               │
│  3. Извлечение номера DC (DC 1..5)                     │
│  4. Упаковка в WebSocket фреймы (RFC 6455)             │
│  5. Fallback на Cloudflare Worker при ошибках WSS      │
└───────────────────────────┬────────────────────────────┘
                            │ WSS / HTTPS (Порт 443)
┌───────────────────────────▼────────────────────────────┐
│         Telegram DC Web Gateways / Cloudflare          │
└────────────────────────────────────────────────────────┘
```

### Преимущества Go-реализации:
- Компилируется в `.aar` библиотеку с помощью `gomobile bind` или нативный бинарник под архитектуры `arm64-v8a`, `armeabi-v7a`, `x86_64`.
- Вес бинарного кода: ~3–5 МБ.
- Потребление RAM: < 10 МБ.
- Встроенная высокопроизводительная модель горутин для сокетов и встроенная криптография (`crypto/aes`, `crypto/cipher`, `crypto/tls`).

## 4. Реализованная архитектура и компоненты порта

### 1. Высокопроизводительное сетевое ядро на Go (`core/`)
- **`pkg/proto`**: Константы протокола MTProto, шлюзы Telegram Web (`kws{dc}.web.telegram.org/apiws`), `MsgSplitter` (RFC-совместимый парсинг фрейминга Abridged `0xef` и Intermediate `0xee`/`0xdd`).
- **`pkg/crypto`**: AES-128-CTR обфускация, SHA-256 деривация ключей с секретом прокси, генерация 64-байтного `relayInit` с определением целевого DC (1..5) и флага media.
- **`pkg/faketls`**: Валидация TLS ClientHello по HMAC-SHA256 и временной метке (допуск 120 сек), сборка валидного ServerHello, поток `FakeTLSConn` с упаковкой в TLS Application Data (`0x17 03 03`).
- **`pkg/ws`**: Высокопроизводительный клиент WebSocket (RFC 6455) over TLS 443 с маскированием кадров и поддержкой буферизации.
- **`pkg/relay`**: Асинхронный двунаправленный релей с перешифрованием (`clt_dec -> tg_enc -> ws` и `ws -> tg_dec -> clt_enc -> clt`) и счетчиками трафика.
- **`pkg/proxy`**: Сетевой сервер, диспетчер подключений и fallback на Cloudflare Worker.
- **`cmd/proxy`**: CLI-утилита (`tg-ws-proxy.exe` под Windows и `libtgproxy.so` под Android).

### 2. Полноценное Android-приложение (`android/`)
- **`TgWsProxyService`**: Foreground Service со специальным типом `specialUse` (API 34+), постоянным уведомлением в шторке, кнопками быстрого отключения и подключения к Telegram.
- **`NativeProxyRunner`**: Запуск скомпилированного бинарника ядра `libtgproxy.so` из `nativeLibraryDir` с удержанием `WakeLock` и `WifiLock` (защита от засыпания в Doze Mode).
- **`MainActivity`**: Интерфейс в стиле Material 3:
  - Индикатор состояния (зеленый/красный) с отображением порта и адреса (`127.0.0.1:1443`);
  - Кнопка «Подключить в Telegram» (мгновенный переход через Intent `tg://proxy?...`);
  - Поля настройки порта, Fake TLS SNI и секрета;
  - Потоковый просмотр журналов ядра в реальном времени.

## 5. Инструкции по сборке и запуску

### Запуск ядра на ПК (Windows/Linux):
```bash
cd core
go run ./cmd/proxy
# или запуск скомпилированного бинарника:
.\tg-ws-proxy.exe -listen 127.0.0.1:1443 -secret eed41d8cd98f00b204e9800998ecf8427e676f6f676c652e636f6d
```

### Сборка Android APK:
```bash
cd android
.\gradlew.bat assembleDebug
```
Собранный APK находится по адресу:
`android/app/build/outputs/apk/debug/app-debug.apk` (включает нативные библиотеки под `arm64-v8a`, `armeabi-v7a`, `x86_64`).
